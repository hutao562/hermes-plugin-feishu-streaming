## 问题根因

Hermes 自动更新是**原子流程**：拉新代码覆盖 `gateway/run.py`（清掉 AST hook）→ 立即 `gateway restart`。补丁永远赶不上这趟车——即使几秒后重打 `install`，也得再 restart 一次才生效（这次失效就是补丁打了但没 restart）。另外 `background watcher` 的 `on_bg_watcher_notify` 手贴 hook **完全丢失**（源码有接收函数，run.py 里 0 处调用，备份也没有）。

## 方案：三层防御 + bg_watcher 自动化

### 第 1 层：`register()` 启动时自愈（核心）

利用已声明但未启用的 `hermes_agent.plugins` entry point（`pyproject.toml:20` 已配），给 `hermes_lark_streaming/__init__.py` 加 `register(ctx)` 函数。插件 discovery 在网关启动时调用（`gateway/run.py:6899` 的 `discover_plugins()`），此时 run.py 已加载但消息 hook 还没触发。

`register()` 逻辑：
1. `Patcher().is_fully_patched()` 检测 run.py 磁盘标记。
2. 若未完整打补丁（升级抹掉了）：跑 `verify_target()` + `apply()` 原地自愈重打；写 `~/.hermes/.hermes_lark_selfhealed` 标记。
3. **关键**：自愈改的是磁盘文件，当前进程内存里仍是旧 run.py。检测到"刚自愈过"→ 算出 `sys.executable` + launchd 服务标签 `ai.hermes.gateway`，用 `launchctl kickstart` 触发一次优雅重启，让网关带着补丁重新加载。通过比较 run.py mtime 与进程启动时间判断"本进程是否加载了补丁版"。
4. 全程日志走 `gateway.run` logger（AGENTS.md 已记录 hermes_lark_streaming logger 不进 gateway.log 的问题）。
5. `verify_target()` 失败（hermes 改了函数名）→ 只记日志不 crash，降级为"等手动 reinstall"，不阻塞网关启动。

`register()` 还注册一个 `pre_gateway_dispatch` hook（`run.py:8913` 每条用户消息触发）作为**运行时健康检查**：首条消息时确认 controller 真的被调用过（记录一个进程内 flag），若 controller 一直没被实例化说明 hook 没注入进运行中的进程——记 warning 日志，提示用户 restart。

### 第 2 层：launchd WatchPaths 守护（双保险）

新增 `scripts/com.hermes-lark.watchdog.plist`（模板）+ 安装逻辑。监听 `~/.hermes/hermes-agent/gateway/run.py` 文件变化，一变就跑 `uninstall && install && launchctl kickstart`。这样即使 `register()` 路径出问题（比如插件没 enable），Hermes 更新覆盖 run.py 的瞬间守护进程也会重打补丁。由 `install` 命令自动安装到 `~/Library/LaunchAgents/`，`uninstall` 命令移除。

### 第 3 层：`status` 加运行时检测 + 完善 reinstall 脚本

- `status` 命令新增：检测当前运行中的网关进程（`pgrep -f "gateway run"`）启动时间 vs run.py mtime，若 run.py 在进程启动后被改过（即补丁是后打的）→ 明确打印 `⚠️ hooks patched but NOT loaded by running gateway — restart needed`。这能直接暴露这次失效的症状（之前 status 显示全 installed 但实际不工作）。
- `status` 的 `Feishu credentials: MISSING` 改为从 `.env` 文件读（`~/.hermes/.env`），而不是只读 `os.environ`——修复这次的误报。
- `reinstall_after_upgrade.sh` 的 step 5.5（bg_watcher）改为真正自动修复（调用新的 patcher bg_watcher 注入），而不是只打印警告。restart 命令统一为 `$HERMES_PYTHON -m hermes_cli.main gateway restart`（脚本现在用的是 `hermes gateway restart`，依赖 PATH 里有 `hermes`）。

### bg_watcher 纳入 patcher.py 自动注入

给 `patcher.py` 加：
- `MK_BG_WATCHER_FINISHED` / `MK_BG_WATCHER_RUNNING` 两个 marker 对（注入点 12 拆成两处）。
- `_find_bg_watcher_finished_site` + `_find_bg_watcher_running_site`：AST 定位 `"finished with exit code"` 字符串所在分支的 `adapter.send(...)` 调用前，和 `"is still running"` 字符串所在分支的 `adapter.send(...)` 前（基于当前 run.py:15661 和 15691 的 `await adapter.send(` 锚点）。注入 `await on_bg_watcher_notify(...)` 并在返回 True 时 `break`/跳过原 adapter.send。
- `verify_target()` 加这两个字符串锚点的存在性检查。
- 加入 `MARKERS` / `_inject_all()` / `is_fully_patched()` 的循环。

这样新的 `install` 会自动打上 bg_watcher 两处注入，和其它 14 个 hook 一样自动化，不再依赖手贴。

### config.yaml 自动 enable 插件

`install` 命令末尾新增：读 `~/.hermes/config.yaml` 的 `plugins.enabled`（JSON 数组字符串），若不含 `hermes-lark-streaming` 则追加写回（用 hermes 自己的 config 写法，保持单行字符串格式）。`uninstall` 命令对应移除。这样 `register()` 自愈才会被调用。

## 改动文件清单

1. **`hermes_lark_streaming/__init__.py`** — 加 `register(ctx)` 自愈函数 + `pre_gateway_dispatch` 运行时健康检查 hook。
2. **`hermes_lark_streaming/patcher.py`** — 加 bg_watcher 两个 marker + 两个 `_find_*_site` + 两个 hook 生成器 + verify 锚点 + MARKERS/is_fully_patched/inject_all 循环。
3. **`hermes_lark_streaming/__main__.py`** — `install` 加：装 watchdog plist + enable config 插件；`uninstall` 加：移除 watchdog + disable config；`status` 加运行时检测 + `.env` 凭据读取。
4. **`scripts/com.hermes-lark.watchdog.plist`**（新）— launchd WatchPaths 守护模板。
5. **`reinstall_after_upgrade.sh`** — step 5.5 改自动修复、restart 命令统一、加 watchdog 自检。
6. **`AGENTS.md`** — 更新架构说明（register 自愈、watchdog、bg_watcher 自动注入）。
7. **测试**：`tests/test_patcher.py` 加 bg_watcher 注入用例；新增 `tests/test_selfheal.py` 覆盖 register() 自愈逻辑（mock Patcher）。

## 验证步骤

1. `ruff check` + `mypy` + `pytest tests/ -q` 全绿。
2. 手动：`uninstall && install` → 确认 bg_watcher 4 处注入 + watchdog plist 装上 + config 插件 enabled。
3. `status` 显示运行时检测正确（本机现在就是"补丁打了没加载"的状态，正好验证）。
4. 模拟升级：`cp run.py.hermes_lark.bak run.py`（还原成无补丁）→ 重启网关 → 观察 `register()` 自愈日志 + 自动 kickstart → 确认第二次启动后卡片恢复。

## 注意

- `register()` 触发的 kickstart 会造成"升级后第一次启动 → 自愈 → 立即重启 → 第二次启动带补丁"，网关会短暂闪启一次（几秒）。这是 Python 无法热重载 run.py 的固有限制，可接受。
- launchd WatchPaths 守护在编辑 run.py 的瞬间会触发，开发时频繁改 run.py 可能反复 kickstart——守护脚本加 5s 防抖（fswatch/throttle）。
- 改了 patcher.py（加 bg_watcher）后，按 AGENTS.md 约定必须 `uninstall && install` 重打 hook。
